# Техническое задание: сайт «Фильмилег»

## 1. Назначение проекта

«Фильмилег» — веб-сайт для выбора и просмотра фильмов, по концепции близкий к онлайн-кинотеатру/каталогу фильмов наподобие Кинопоиска.

Сайт должен предоставлять обычному пользователю каталог фильмов, поиск, просмотр видео, аккаунт пользователя и персональное избранное. Для пользователей с административным доступом должна существовать отдельная страница управления содержимым сайта.

Документ описывает требуемое поведение сайта и основные функции. Конкретные технологии серверной части, базы данных и реализации авторизации в этом ТЗ не фиксируются, если они отдельно не определены в проекте.

## 2. Дизайн и интерфейс

- Сайт должен иметь единый аккуратный дизайн.
- Для реализации интерфейса используется Bootstrap.
- Основные страницы и элементы интерфейса должны выглядеть как части одного сайта.
- Интерфейс должен быть удобен для обычного пользователя.
- Навигация между главной страницей, каталогом/поиском, избранным, аккаунтом и просмотром фильма должна быть понятной.

## 3. Главная страница

Главная страница должна предоставлять пользователю доступ к каталогу фильмов и основным функциям сайта.

Для каждого фильма в каталоге должны быть доступны как минимум действия:

- открыть страницу/просмотр фильма;
- добавить фильм в избранное;
- убрать фильм из избранного, если он уже добавлен.

Главная страница также должна предоставлять доступ к избранному пользователя.

## 4. Каталог фильмов

Сайт должен хранить и отображать список доступных фильмов.

Для каждого фильма должна существовать информация, необходимая для его отображения и просмотра. Администратор должен иметь возможность редактировать эти данные.

Минимально должна поддерживаться возможность:

- добавлять новые фильмы;
- изменять существующие фильмы;
- удалять фильмы;
- изменять название фильма;
- изменять остальные доступные данные фильма;
- открывать фильм для просмотра.

## 5. Поиск

На сайте должен быть реализован полноценный поиск фильмов.

Поиск должен позволять пользователю находить фильмы по их названию и возвращать соответствующие результаты из существующего каталога.

Результаты поиска должны отображаться в интерфейсе сайта и позволять перейти к просмотру выбранного фильма или добавить его в избранное.

Поиск не должен создавать или придумывать фильмы, которых нет в каталоге.

## 6. Просмотр фильма

Пользователь должен иметь возможность открыть фильм и просмотреть его непосредственно через сайт.

На странице просмотра должно быть доступно видео фильма.

Страница просмотра должна быть связана с конкретным фильмом из каталога, чтобы пользователь понимал, какой фильм он смотрит.

## 7. Пользовательский аккаунт

Сайт должен поддерживать аккаунты обычных пользователей.

Для аккаунта должны сохраняться как минимум:

- никнейм пользователя;
- пароль пользователя;
- аватар пользователя;
- список фильмов, добавленных пользователем в избранное.

Данные аккаунта должны сохраняться между посещениями сайта.

## 8. Авторизация и регистрация

Пользователь должен иметь возможность войти в свой аккаунт.

Для идентификации аккаунта должен использоваться никнейм и пароль.

После успешной авторизации сайт должен понимать, какой именно пользователь сейчас работает с сайтом, чтобы привязывать к его аккаунту персональные данные, включая избранное.

Пароль не должен отображаться другим пользователям в открытом виде.

## 9. Изменение аккаунта

Авторизованный пользователь должен иметь возможность изменять данные своего аккаунта.

Должны поддерживаться как минимум:

- изменение никнейма;
- изменение аватара;
- сохранение новых данных аккаунта.

После изменения данных новые значения должны использоваться сайтом при последующих входах и отображении аккаунта.

## 10. Избранное

Избранное является персональной функцией пользователя.

Пользователь должен иметь возможность добавить фильм в избранное с главной страницы/каталога.

Избранное должно быть привязано именно к аккаунту пользователя. Один пользователь не должен видеть в своём избранном фильмы, добавленные другим пользователем.

Пользователь должен иметь возможность:

- добавить фильм в избранное;
- удалить фильм из избранного;
- открыть список избранных фильмов;
- перейти к просмотру фильма из избранного.

Доступ к избранному должен быть возможен как минимум из двух мест:

1. с главной страницы;
2. со страницы аккаунта пользователя.

После повторного входа в аккаунт список избранного должен сохраняться.

## 11. Страница аккаунта

У пользователя должна существовать отдельная страница аккаунта.

На странице аккаунта должна отображаться информация, связанная с текущим пользователем, включая его никнейм и аватар.

Со страницы аккаунта пользователь должен иметь доступ к своему избранному и настройкам/изменению данных аккаунта.

## 12. Административный доступ

Сайт должен иметь отдельный режим для пользователей с административным доступом.

Административный доступ должен предоставляться только пользователю, которому он назначен.

Доступ к административной странице должен осуществляться через специальную проверку доступа. В зависимости от реализации проекта идентификация администратора может выполняться по специальному паролю, никнейму или другому заранее назначенному признаку доступа.

Обычный пользователь без административных прав не должен иметь возможности выполнять административные действия.

## 13. Страница администрирования

Для администратора должна существовать отдельная страница редактирования сайта.

Администратор должен иметь возможность управлять содержимым каталога фильмов.

Минимальный набор административных действий:

- добавление нового фильма;
- удаление существующего фильма;
- редактирование существующего фильма;
- изменение названия фильма;
- изменение остальных данных фильма;
- управление данными, необходимыми для просмотра фильма.

Изменения, выполненные администратором, должны сохраняться и становиться доступны обычным пользователям сайта.

## 14. Разделение прав

Необходимо разделять права обычного пользователя и администратора.

### Обычный пользователь может:

- просматривать каталог;
- выполнять поиск;
- смотреть фильмы;
- регистрироваться и входить в аккаунт;
- изменять собственный никнейм;
- изменять собственный аватар;
- просматривать собственное избранное;
- добавлять фильмы в собственное избранное;
- удалять фильмы из собственного избранного.

### Администратор дополнительно может:

- открывать административную страницу;
- добавлять фильмы;
- удалять фильмы;
- редактировать фильмы;
- изменять названия и остальные данные фильмов;
- управлять содержимым каталога.

Администраторские возможности не должны быть доступны обычному пользователю только за счёт перехода по URL административной страницы.

## 15. Сохранение данных

Сайт должен сохранять данные, которые должны переживать завершение пользовательской сессии.

В частности, должны сохраняться:

- данные аккаунта пользователя;
- никнейм;
- пароль в безопасном виде;
- аватар;
- список избранных фильмов;
- данные каталога фильмов;
- изменения, внесённые администратором.

## 16. Основной пользовательский сценарий

1. Пользователь открывает сайт.
2. Пользователь видит доступные фильмы.
3. Пользователь может найти нужный фильм через поиск.
4. Пользователь открывает фильм и запускает просмотр.
5. Пользователь может добавить фильм в избранное.
6. Пользователь открывает раздел «Избранное» с главной страницы или из аккаунта.
7. Пользователь видит только фильмы, добавленные в избранное его аккаунтом.
8. Пользователь может открыть любой фильм из избранного.
9. Пользователь может изменить никнейм или аватар в аккаунте.
10. Пользователь выходит из аккаунта и позже входит снова.
11. Его данные и избранное должны сохраниться.

## 17. Основной административный сценарий

1. Пользователь с административным доступом проходит проверку прав.
2. Открывается административная страница.
3. Администратор просматривает существующие фильмы.
4. Администратор может добавить новый фильм.
5. Администратор может изменить существующий фильм, включая его название и другие данные.
6. Администратор может удалить фильм.
7. Изменения сохраняются.
8. Обычные пользователи после сохранения видят актуальное содержимое каталога.

## 18. Требования к безопасности

- Административные действия должны быть защищены проверкой прав доступа.
- Обычный пользователь не должен иметь возможности выполнять административные операции.
- Пароли пользователей нельзя хранить в открытом виде.
- Пользователь должен иметь доступ только к собственным персональным данным и собственному избранному.
- Нельзя считать наличие или отсутствие ссылки на административную страницу достаточной защитой.

## 19. Критерии готовности

Сайт считается соответствующим данному ТЗ, если реализованы следующие основные возможности:

- существует каталог фильмов;
- работает поиск фильмов;
- фильмы можно просматривать через сайт;
- существует регистрация/авторизация пользователей;
- сохраняются никнейм, пароль и аватар пользователя;
- пользователь может изменить никнейм и аватар;
- существует персональное избранное;
- избранное сохраняется отдельно для каждого пользователя;
- избранное доступно с главной страницы и страницы аккаунта;
- пользователь может добавлять и удалять фильмы из избранного;
- существует административная страница;
- администратор может добавлять, удалять и редактировать фильмы;
- административные права отделены от прав обычного пользователя;
- интерфейс сайта реализован с использованием Bootstrap;
- изменения данных сохраняются и не теряются после завершения сессии.

## 20. Что не фиксируется данным ТЗ

Данное ТЗ намеренно не навязывает конкретный язык программирования, серверный фреймворк, СУБД, способ хранения видео, способ размещения сайта или конкретную архитектуру проекта, если эти решения не были отдельно определены в проекте.

Цель документа — зафиксировать требуемое поведение и функциональность сайта «Фильмилег», а не выдумывать технические решения вместо реализации.
